# ADR 0003. Биоритмы вычисляются, а не хранятся

**Статус:** принято · 2026-10-27

## Контекст

Значение цикла — `sin(2π · t / P)`, где `t` — время от рождения в сутках. Расчёт занимает микросекунды. Хранение значений по дням или часам дало бы таблицу, которую нужно пересчитывать при каждом изменении даты, времени или пояса рождения.

## Решение

- В БД хранятся только исходные данные: `user_profiles.birth_date`, `birth_time`, `birth_time_known`, `birth_tz` и вычисленный из них `birth_at_utc`.
- Значения циклов, фазы и критические дни считает `biorhythm/engine.py` по запросу.
- Готовые ряды кэшируются в Redis с TTL 24 ч; ключ содержит хэш данных рождения и пояс (`bio:{user_id}:{birth_hash}:{tz}:{from}:{to}:{step}`), поэтому при их изменении старые ключи просто истекают.
- Итог дня, на котором построено расписание, сохраняется в `schedules`: `critical_level`, `load_factor` и снимок значений циклов в `summary` (jsonb). Это нужно для истории версий и объяснений.

## Последствия

- Нет миграций данных при изменении алгоритма — только смена `algorithm_version`.
- Клиент может считать то же самое офлайн по константам из `/meta/algorithm`.
